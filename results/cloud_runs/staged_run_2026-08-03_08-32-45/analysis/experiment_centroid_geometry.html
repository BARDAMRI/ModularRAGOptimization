Group Definitions

Three geometric groups partition the document pool per query, each defined as all pool documents inside a cosine-distance circle in embedding space.

GroupCircle centerRadiusMembership rule
G1 Query vector Q r₁ = dist(Q, GT) dist(doc, Q) ≤ r₁
G2 Normalized centroid of G3 r₂ = dist(centroid, GT) dist(doc, centroid) ≤ r₂
G3 - - LLM score = 1.0

Distance = 1 − dot(a, b) for L2-normalised vectors. All DB vectors are unit vectors (HuggingFaceEmbedding normalize=True).

§ 3

Experiment 2 - Halfpoint Experiment (Random Space Points)

To test whether the GT neighborhood is inherently dense, 10 random unit vectors are generated per query at exactly cosine distance r₁/2 from GT. Each anchor's circle has radius r₁/2 - same distance-to-GT as a typical centroid, matching G2's convention.

Construction (Gram-Schmidt)

u_perp = v − dot(v, GT) · GT      # remove GT component
u_perp /= ‖u_perp‖                # unit vector ⊥ GT
anchor = cos(θ)·GT + sin(θ)·u_perp  # where cos(θ) = 1 − r₁/2

Verification: dot(anchor, GT) = cos(θ) → cosine_distance(anchor, GT) = r₁/2 ✓

Experiment 3 - Pool-Document Centroid Experiment

Instead of synthetic random points, use actual pool documents as circle centers. For each query, find pool docs where dist(doc, GT) < r₁ (closer to GT than the query), sample up to 10, and use each as a center with radius = dist(doc, GT) - identical convention to G2.

This tests whether the pool itself is structurally dense around GT.

§ 5

Unified Interpretation

The Query–Document Gap

Queries and documents occupy different regions of embedding space. Because the retriever returns GT as the nearest document to Q, almost nothing in the pool is closer to Q than GT - G1 collapses to 1–3 docs on average. Documents near GT, however, are surrounded by other semantically similar documents. The pool clusters around GT in document space.

§ 6

Conclusions

1

G2 systematically outperforms G1

In 77.6% of 196 queries, G2 captures more documents (~3× on average: 9.72 vs 3.13). The centroid anchors the circle inside the dense document cluster, not in query space.

2

The GT neighborhood is not uniformly dense

Random points at equal distance from GT capture only 0.82 docs - fewer than G1. The density advantage requires real document structure, not just proximity to GT.

3

The document pool is structured around GT

Real pool docs closer to GT than Q capture 10.12 docs (91.8% of queries beat G1). The pool is not uniform - it concentrates near semantically relevant content.

4

The query–document gap drives the disparity

Queries sit in a different embedding region than documents. Using Q as the circle center misses the document cluster entirely - G1's radius r₁ is "wasted" on empty query space.

5

The centroid is special in density, not in raw count

Any real pool doc near GT gives similar raw count (~10). The centroid has uniquely high density (92.5 vs 59.6) because it minimizes total cluster distance, yielding the smallest radius for the same coverage.
