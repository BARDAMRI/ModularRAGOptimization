Terminology

Key Terms

TermMeaning
Query (Q)The search query, represented as an embedding vector in 768-dimensional space.
GT (Ground Truth)The single correct document for a given query — the document the retriever is supposed to find.
PoolThe full set of 5,035 candidate documents that are ranked for each query.
r1The cosine distance between Q and GT: r1 = dist(Q, GT). It is the "gap" the retriever must close — smaller r1 means GT is already close to Q in embedding space.
Cosine distance1 − dot(a, b) for L2-normalised vectors. Ranges from 0 (identical) to 2 (opposite). All vectors here are L2-normalised, so dot product equals cosine similarity.
BFS rankThe position of GT when all pool documents are sorted by a scoring function f (rank 1 = closest / best). Lower rank = fewer steps to find GT.
G3Documents that received a perfect relevance score (1.0) from the LLM judge. Mean size: 17 docs per query.
CentroidThe normalised mean embedding of all G3 documents for a given query. Acts as a "centre of mass" of the relevant cluster. This is an oracle — it requires LLM scores and is not available at real retrieval time.
Q_CIRCLE / GT_CIRCLEThe set of pool documents that fall within a circle of radius r1/2, centred on Q or GT respectively.
Top-1 / Top-10Percentage of queries where GT lands at rank 1 (or within the top 10) under a given strategy.
Experiment 1

Q_CIRCLE vs GT_CIRCLE — radius = r1/2

Do query vectors have neighbours in document space, the same way GT vectors do?

Setup. For every query, draw two circles of radius r1/2 — one centred on Q, one on GT — and count how many pool documents fall inside each. GT is excluded from its own circle.

r1 = dist(Q, GT) [cosine distance] radius = r1 / 2 Q_CIRCLE = { doc ∈ pool : dist(doc, Q) ≤ radius } GT_CIRCLE = { doc ∈ pool : dist(doc, GT) ≤ radius } \ { GT itself }

Finding — hypothesis confirmed (absolutely) Q_CIRCLE is empty in every single one of the 196 queries. No pool document falls within r1/2 of any query vector. GT_CIRCLE, by contrast, has at least one neighbour in 23% of queries (up to 12 docs). The asymmetry is total: queries are geometric outliers in document space — not a matter of threshold, but of structure.
Caveat At radius r1/2 (mean ≈ 0.087 cosine), both circles are small relative to a 5,035-doc pool in 768D. 77% of queries have GT_CIRCLE empty as well, so the comparison is uninformative for those. The asymmetry is still decisive: GT sometimes has neighbours; Q never does.
Experiment 2

BFS Rank Comparison — Strategies for Finding GT

Does mixing centroid distance into the retrieval function improve GT recovery?

Setup. Rank all 5,035 pool documents by a scoring function f. The rank of GT equals the number of BFS steps needed to reach it. Lower = better. The centroid is the normalised mean embedding of G3 docs (LLM score = 1.0) — an oracle not available at real retrieval time.

Baseline 1 : f = dist(Q) Baseline 2 : f = dist(Centroid) [oracle] Hybrid 1 : f = α·dist(Q) + β·dist(Centroid), α > β > 0 Hybrid 2 : f = (dist(Q), dist(Centroid)) [lexicographic] Hybrid 3 : top-k by dist(Q) → rerank by dist(Centroid)

The sweet spot is α = 0.93: it achieves the best top-1 accuracy (71.4%) while keeping mean rank equal to Baseline 1 (3.3). At α = 0.91 the same top-1 is reached, but mean rank worsens to 3.4 — so 0.93 Pareto-dominates 0.91. The gain over pure dist(Q) is only +1.0 percentage point (≈ 2 queries out of 196), and top-10 drops by 1%, so the practical benefit is marginal. Note that the constraint α + β = 1 is without loss of generality: only the ratio α/β affects ranking order.

Synthesis

Conclusions

✓ Queries are geometric outliers

Zero pool documents within r1/2 of any query vector, across all 196 queries. GT has neighbours in 23% of cases. The gap is structural, not a threshold effect.

~ Centroid gives marginal top-1 gain

Best hybrid (α=0.93): top-1 rises from 70.4% to 71.4% (+1%, ≈2 queries). Mean rank unchanged at 3.3. Top-10 loses 1%. No strategy dominates Baseline 1 on all metrics.

Two conflicting objectives

Coverage (G2 > G1): centroid wins — finds the relevant cluster.
Precision (rank GT first): dist(Q) wins — GT is the nearest neighbour in 70% of cases. Mixing dilutes precision.

Oracle caveat

The centroid is built from G3 (LLM-scored docs) — unavailable at retrieval time. These results are upper bounds. Hybrid 3 at k≥50 approximates a real centroid estimate and shows no gain.

Open question The 45 queries where GT_CIRCLE is non-empty — do they overlap with the ≈8% of queries where Hybrid 1 beats Baseline 1? If so, the centroid could be applied selectively (a routing strategy) rather than universally — only when there is evidence of a tight document cluster around GT.
